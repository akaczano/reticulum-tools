## Reticulum Proof of Concept Repo

This repository contains an assortment of proof of concept tools for the testing and exploration of the
reticulum network stack (RNS). So far the main one is called 'RNS Server'

### RNS Server
The RNS Server utility is an application server designed with two main goals in mind:

1. To provide easy access to the reticulum network stack over REST and expose some of the basic built-in RNS utilities over HTTP. This will allow users to do things like view the path table, see connected interfaces, etc. using HTTP requests generated by a web browser.

2. To provide a simple messaging service running over reticulum.

#### Endpoints

- `/interfaces` View all of the interfaces that reticulum is connected to
- `/paths` See the current state of the path table
- `/contacts` See the other reticulum server applications that this app has discovered and the names associated
- `/messages` See all of the messages this app has received
- `/send` Sends a message. Requires a json body that looks like this:
    ```json
    {
        "user": 1,
        "message": "Hello"
    }
    ```
    Where `user` is the ID from the contacts output and `message` is the raw text of the message to send.


#### Containerized Testing

To get a simple, containerized test network up and running, you can do the following:

1. From the `rns-server` directory, run the following:

    `make messenger-node`

2. Go into `rns-server/tests` and start up the services using `docker compose up -d`

3. It should start up the following containers:

    - gordon
    - todd
    - transport
    - roger

4. Gordon, Todd, and Roger all have their rns-server exposed on ports 5001, 5002, and 5003 respectively. Doing `curl http://localhost:5001/interfaces` should show you what interfaces Gordon is conntected to. Doing `curl http://localhost:5001/contacts` will show you what other people he sees.

5. Go into `rns-server/tests/scripts` to run scripts that autopopulate the curl commands

    - `get_contacts.sh` runs the contacts URL from step 4
    - `get_interfaces.sh` runs the interfaces URL from step 4
    - `send_message.sh` will send a message from one user to another

#### Source Code

All of the source code exists in the `rns-server/src` directory. It contains the following files

- `app.py` The entrypoint and REST API implementation
- `rns_server.py` The service that talks to the network stack
- `tables.py` Contains classes mapped to database tables by the ORM.
